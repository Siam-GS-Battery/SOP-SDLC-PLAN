# 4.1.1 Dependencies Checklist (แบ่งตามประเภทแอป)

> ✅ **วิธีใช้:** ติดตั้ง **Tier 0 (Base)** ก่อน แล้วเลือก Tier อื่นเฉพาะที่แอปคุณต้องการ

เอกสารนี้ใช้เป็น reference ตอนเริ่มโปรเจกต์ใหม่ — เลือก dependency ตามชนิดแอปที่จะทำ ไม่ต้องลงทุกอย่าง

## ⚙️ BACKEND

### ☑️ Tier 0 — Base + Security (ทุก API ต้องมี)

```bash
npm install express@^4.21.0 cors@^2.8.5 \
  helmet@^8.0.0 compression@^1.7.4 morgan@^1.10.0 \
  express-rate-limit@^7.4.0 \
  dotenv@^16.4.5 zod@^3.23.8

npm install -D typescript@^5.5.0 tsx@^4.16.0 \
  @types/node @types/express @types/cors \
  @types/morgan @types/compression \
  eslint @typescript-eslint/eslint-plugin @typescript-eslint/parser prettier
```

**Setup checklist:**

- [ ] `app.use(helmet())` — security headers
- [ ] `cors` whitelist (ไม่ใช่ `*`)
- [ ] `compression()` เปิด gzip
- [ ] `morgan('combined')` ใน production
- [ ] `express-rate-limit` 100 req / 15 min บน `/api`
- [ ] Global error handler ที่จัดการ `ZodError → 400`
- [ ] `/api/health` endpoint
- [ ] `.env.example` + `.env` ใน gitignore
- [ ] tsconfig strict mode = true

### ☑️ Tier 1 — Auth (JWT + bcrypt)

ใช้เกือบทุก API ที่มี user

```bash
npm install bcryptjs@^2.4.3 jsonwebtoken@^9.0.2
npm install -D @types/bcryptjs @types/jsonwebtoken
```

**Setup checklist:**

- [ ] `JWT_SECRET` ≥ 32 bytes (สร้างจาก `openssl rand -hex 32`)
- [ ] bcrypt cost ≥ 10
- [ ] Access token 15-30 นาที + refresh token แยก
- [ ] `requireAuth` middleware ใส่ `algorithms: ['HS256']` ใน `verify`
- [ ] Login endpoint มี strict rate limit (5 / 15 min)
- [ ] ห้าม log password / token

---

### ☑️ Tier 2 — Database (เลือก 1 จาก 2)

#### Option A: Supabase (default)

```bash
npm install @supabase/supabase-js@^2.45.0
```

**Setup checklist:**

- [ ] `SUPABASE_SERVICE_ROLE_KEY` อยู่ฝั่ง backend เท่านั้น
- [ ] Frontend ใช้ `SUPABASE_ANON_KEY` + RLS
- [ ] เปิด Row Level Security (RLS) ทุก table
- [ ] เขียน policy ครบทุก operation

#### Option B: PostgreSQL ตรง

```bash
npm install pg@^8.18.0
npm install -D @types/pg
```

**Setup checklist:**

- [ ] Connection pool config (`max`, `idleTimeoutMillis`)
- [ ] Parameterized queries เท่านั้น (`$1, $2`) — ห้าม string concat
- [ ] Migration tool (เช่น node-pg-migrate)

---

### ☑️ Tier 3 — File Upload

ใช้เมื่อรับ upload จาก user

```bash
npm install multer
npm install -D @types/multer
```

**Setup checklist:**

- [ ] จำกัด file size (`limits: { fileSize: 10 * 1024 * 1024 }`)
- [ ] Whitelist MIME type (ตรวจ magic bytes ด้วย ไม่เชื่อ extension)
- [ ] Random filename (UUID) — ห้ามใช้ original
- [ ] เก็บไฟล์ใน Supabase Storage หรือ S3 (ไม่ใช่ disk เครื่อง)

---

### ☑️ Tier 4 — External Storage (S3)

ใช้เมื่อต้องเก็บไฟล์เอง ไม่ใช้ Supabase Storage

```bash
npm install @aws-sdk/client-s3 @aws-sdk/s3-request-presigner
```

**Setup checklist:**

- [ ] IAM user สิทธิ์ขั้นต่ำ (เฉพาะ bucket ที่ใช้)
- [ ] Presigned URL หมดอายุ ≤ 1 ชม.
- [ ] Bucket policy ปิด public access (ใช้ presigned)

## 🔒 Security Checklist (รวมทุก project)

ตรวจตอน setup เสร็จ ก่อนขึ้น production

- [ ] `.env` อยู่ใน `.gitignore` (ไม่ commit)
- [ ] `.env.example` มีแต่ key (ไม่มี value จริง)
- [ ] `JWT_SECRET` ≥ 32 bytes random
- [ ] bcrypt cost ≥ 10
- [ ] CORS whitelist origin (ไม่ใช่ `*`)
- [ ] helmet เปิดใช้งาน
- [ ] Rate limit ทั่วไป + เข้มงวดบน auth
- [ ] Zod validate ทุก endpoint
- [ ] Supabase RLS เปิดทุก table
- [ ] HTTPS only ใน production
- [ ] `npm audit` ผ่าน (ไม่มี high/critical)
- [ ] ห้าม log password / token / PII
- [ ] Secret ต่างกัน dev / prod
