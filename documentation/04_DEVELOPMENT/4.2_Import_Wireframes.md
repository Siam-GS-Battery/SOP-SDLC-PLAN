# 4.2 Generate UI with Claude

## วัตถุประสงค์

ให้ Claude (Claude Code) สร้าง UI (screens + components) ของโปรเจกต์ จาก **Design System** และ **Acceptance Criteria (AC) / User Stories** โดยตรงในโครงสร้าง Frontend ของโปรเจกต์ — พร้อมสร้าง **DataContext** (mock data + types) เพื่อใช้ต่อใน [4.3 Database from DataContext](4.3_Database_Design.md)

> ทีมไม่ใช้ Figma ในขั้นตอนนี้ — Design System ([2.3](../02_DESIGN/2.3_Design_System_Template.md)) คือแหล่งอ้างอิงด้าน design เดียว

---

## Inputs

| Input | ที่มา | ใช้ทำอะไร |
|-------|------|----------|
| Design System | [2.3 Design System Template](../02_DESIGN/2.3_Design_System_Template.md) | Design tokens (สี, font, spacing), component rules, layout |
| AC / User Stories | Phase 1 Requirements | กำหนดหน้าจอ, flow, validation, edge cases |

| Code Standard | [Code Standard Guide](Code_Standard_Guide.md) | Naming, folder structure |

## 1. สั่ง Claude สร้าง UI

### 1.1 เตรียม Context

เปิด Claude Code ที่ root ของโปรเจกต์ และให้ Claude อ่านไฟล์เหล่านี้ก่อน (ใช้ `@` อ้างไฟล์ หรือใส่ไว้ใน `CLAUDE.md`):

- Design System (2.3) และ AC / User Stories
- โครงสร้าง `frontend/src/` ที่ตั้งไว้ใน 4.1

### 1.2 เขียน Prompt จาก AC

สั่งทีละ feature/หน้า (ไม่สั่งทั้งแอปรวดเดียว):

```
ตัวอย่าง prompt:
"อ่าน @documentation/02_DESIGN/2.3_Design_System_Template.md และ AC ของ feature Product
สร้างหน้า Product listing ใน frontend/src/pages/ และ components ใน frontend/src/components/features/products/
- ใช้ design tokens จาก Design System เท่านั้น (ห้าม hardcode สี/ขนาด)
- มี search bar, category filter, grid layout
- รองรับ loading / empty / error state และภาษาไทย
- สร้าง types + mock data ใน DataContext (frontend/src/context/DataContext.tsx)
- ทำตาม Code Standard Guide"
```

> **Tips:** ยิ่ง prompt อ้าง AC ละเอียด (เงื่อนไข, validation, role) ยิ่งได้ UI ที่ตรงความต้องการ

### 1.3 จัดไฟล์ตาม convention

```
frontend/src/
├── components/
│   ├── common/          ← Button, Input, Modal
│   ├── layout/          ← Header, Footer, Sidebar
│   └── features/        ← Feature-specific components
│       ├── auth/        ← LoginForm, RegisterForm
│       └── products/    ← ProductCard, ProductList
├── context/             ← DataContext (types + mock data)
├── pages/               ← HomePage, ProductPage, CartPage
└── ...
```

> ดูรายละเอียดที่ [Code Standard Guide — Section 2](Code_Standard_Guide.md#2-file--folder-structure)

## 2. ตรวจสอบ UI เทียบกับ Design System

รัน app (`npm run dev`) แล้วตรวจทุกหน้า:

- [ ] ใช้ design tokens จาก Design System (สี, typography, spacing) ไม่ hardcode
- [ ] Component ตรงกับกฎใน Design System (variants, states)
- [ ] ครบทุกหน้า/flow ตาม AC และมี loading / empty / error state
- [ ] Responsive และ accessibility ตามที่ Design System กำหนด
- [ ] Component naming (PascalCase) + import paths ถูกต้อง
- [ ] ลบ code ที่ไม่จำเป็น (unused imports, placeholder)

ถ้าไม่ตรง ให้สั่ง Claude แก้ทีละจุด พร้อมอ้างข้อที่ผิด เช่น "ปุ่มหน้า Cart ไม่ใช้ primary token ตาม Design System ส่วน Buttons"

## 3. เก็บ DataContext ไว้สำหรับขั้นตอนถัดไป

Claude จะสร้าง **DataContext** (types + mock data) ไว้ใน code:

```typescript
// ตัวอย่าง DataContext
export interface Product {
  id: number;
  name: string;
  price: number;
  category: string;
  image: string;
}

const products: Product[] = [
  { id: 1, name: "Product A", price: 500, category: "Electronics", image: "..." },
  { id: 2, name: "Product B", price: 300, category: "Clothing", image: "..." },
];
```

ตรวจว่า entity ครอบคลุมทุกหน้า, field มี type ชัดเจน และความสัมพันธ์ระหว่าง entity (เช่น `categoryId`, `userId`) ถูกต้อง

> **สำคัญ:** เก็บ DataContext ไว้ — ใน [4.3 Database from DataContext](4.3_Database_Design.md) จะใช้ Claude อ่าน DataContext นี้เพื่อสร้าง SQL Schema
