# 4.1.2 Internal NPM Packages (GitHub Packages)

> 📦 จุดประสงค์: ให้ทีมใช้ **ESLint / Prettier / TypeScript config เดียวกัน** ในทุกโปรเจกต์ โดยติดตั้งจาก private NPM registry ของ organization

---

## 1. ทำไมต้องมี Internal Packages?

| ปัญหาเดิม | ใช้ Internal Packages |
|:---|:---|
| Copy `.eslintrc` / `.prettierrc` ทุกโปรเจกต์ | `extends: '@siam-gs-battery/eslint-config'` |
| แก้ rule แล้วต้องไล่อัปเดตทุก repo | bump version ครั้งเดียว ทุกโปรเจกต์ pull ได้ |
| แต่ละทีมตีความ standard ต่างกัน | มี source of truth ที่ versioned |
| ไม่มี audit trail | Git history + npm version |

## 3. Setup สำหรับ Consumer (ทีมที่จะใช้)

### Step 1 — สร้าง Personal Access Token (PAT)

1. ไปที่ https://github.com/settings/tokens (classic)
2. **Generate new token (classic)**
3. ตั้งชื่อ: `npm-read-siam-gs-battery`
4. เลือก scope: ✅ `read:packages`
5. ตั้ง expiration ตามนโยบาย (แนะนำ 90 วัน)
6. **Copy token** (`ghp_xxxxxxxx`) เก็บไว้ — จะแสดงครั้งเดียว

### Step 2 — Export Token ใน Shell

เพิ่มใน `~/.zshrc` หรือ `~/.bashrc`:

```bash
export GITHUB_TOKEN=ghp_xxxxxxxxxxxxxxxxxxxx
```

แล้ว reload:

```bash
source ~/.zshrc
```

> ⚠️ **ห้ามใส่ token ตรงๆ ใน `.npmrc` ที่ commit ลง git** — ใช้ environment variable เท่านั้น

### Step 3 — สร้าง `.npmrc` ใน root ของโปรเจกต์

```ini
@siam-gs-battery:registry=https://npm.pkg.github.com
//npm.pkg.github.com/:_authToken=${GITHUB_TOKEN}
```

ไฟล์นี้ **commit ลง git ได้** เพราะค่าจริงของ token จะถูก resolve จาก env var

### Step 4 — ติดตั้ง Packages

```bash
npm install -D @siam-gs-battery/eslint-config \
               @siam-gs-battery/prettier-config \
               @siam-gs-battery/tsconfig
```

### Step 5 — ใช้งานในโปรเจกต์

**Frontend (Vite + React):**

```js
// .eslintrc.cjs
module.exports = {
  root: true,
  extends: ['@siam-gs-battery/eslint-config/react'],
};
```

```json
// tsconfig.json
{
  "extends": "@siam-gs-battery/tsconfig/react.json",
  "compilerOptions": {
    "baseUrl": ".",
    "paths": { "@/*": ["./src/*"] }
  },
  "include": ["src"]
}
```

```json
// package.json
{
  "prettier": "@siam-gs-battery/prettier-config"
}
```

**Backend (Node.js + Express):**

```js
// .eslintrc.cjs
module.exports = {
  root: true,
  extends: ['@siam-gs-battery/eslint-config/node'],
};
```

```json
// tsconfig.json
{
  "extends": "@siam-gs-battery/tsconfig/node.json",
  "compilerOptions": {
    "outDir": "./dist",
    "rootDir": "./src"
  },
  "include": ["src/**/*"]
}
```

## 4. Setup สำหรับ Maintainer (ทีมที่จะ publish)

### Step 1 — Clone repo

```bash
git clone https://github.com/siam-gs-battery/sop-sdlc-plan.git
cd sop-sdlc-plan
npm install
```

### Step 2 — แก้ไข package

ไปที่ `packages/<package-name>/` แก้ไข rules / config ตามต้องการ

### Step 3 — Bump version (semver)

| ประเภทการแก้ไข | คำสั่ง |
|:---|:---|
| Bug fix / rule clarification | `npm run version:patch` |
| เพิ่ม rule ใหม่ที่ไม่ break | `npm run version:minor` |
| เปลี่ยน rule ที่ทำให้ project พังต้องแก้ | `npm run version:major` |

> ⚠️ **Major version bump = breaking change** — ต้องแจ้งทีมและมี migration guide

### Step 4 — Commit + Tag + Push

```bash
git add .
git commit -m "feat(eslint-config): add no-floating-promises rule"
git tag v0.2.0
git push origin develop --tags
```

### Step 5 — GitHub Actions จะ publish อัตโนมัติ

Workflow `.github/workflows/publish-packages.yml` จะ trigger เมื่อ push tag `v*`

ตรวจสอบที่:

- Actions tab → "Publish Packages to GitHub Packages"
- Repo → Packages tab → ดู version ใหม่

### Dry run (ทดสอบก่อน publish จริง)

ใน Actions → Run workflow → ติ๊ก `dry_run: true`

หรือ local:

```bash
npm publish --workspaces --access restricted --dry-run
```

## 5. CI/CD Integration

ถ้าโปรเจกต์ที่ใช้ packages เหล่านี้ต้อง build ใน GitHub Actions:

```yaml
# .github/workflows/ci.yml (in consumer project)
steps:
  - uses: actions/checkout@v4

  - uses: actions/setup-node@v4
    with:
      node-version: '20'
      registry-url: 'https://npm.pkg.github.com'
      scope: '@siam-gs-battery'

  - name: Install
    env:
      NODE_AUTH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
    run: npm ci
```

> `GITHUB_TOKEN` ที่ workflow ใช้ต้องมี `packages: read` permission

## 6. Troubleshooting

### `401 Unauthorized` ตอน `npm install`

```bash
# ตรวจว่า GITHUB_TOKEN export ใน shell แล้ว
echo $GITHUB_TOKEN

# ตรวจว่า .npmrc อ่าน env var ถูก
npm config get @siam-gs-battery:registry
# ต้องได้: https://npm.pkg.github.com/
```

ถ้ายังไม่ได้ — ตรวจ PAT ว่า:

- ยังไม่หมดอายุ
- มี scope `read:packages`
- ถูก **Authorize SSO** ถ้า org เปิด SSO (ดูที่หน้า token settings)

### `404 Not Found` ตอน `npm install`

- ตรวจชื่อ package: ต้องเป็น `@siam-gs-battery/...` (ขีดกลาง ไม่ใช่ underscore)
- ตรวจว่า version ที่ระบุมีอยู่จริง: `npm view @siam-gs-battery/eslint-config versions --json`

### `npm publish` ขึ้น `403 Forbidden`

- PAT ที่ใช้ publish ต้องมี `write:packages`
- ใน Actions: workflow ต้องมี `permissions: packages: write`
- ตรวจว่า `repository.url` ใน `package.json` ตรงกับ repo จริง

### Version conflict

GitHub Packages **ไม่อนุญาตให้ publish version เดิมซ้ำ** — ต้อง bump version ใหม่ทุกครั้ง

## 7. Maintainer Checklist (ก่อน publish version ใหม่)

- [ ] Update `CHANGELOG` ใน README ของ package ที่แก้
- [ ] Bump version ตาม semver (`npm run version:patch` / `:minor` / `:major`)
- [ ] รัน `npm publish --dry-run --workspaces` ตรวจว่า tarball มีไฟล์ครบ
- [ ] เปิด PR + ให้ Senior review (ตาม [7.3 PR Process](../07_GIT_WORKFLOW/7.3_Pull_Request_Process.md))
- [ ] Merge เข้า `develop` แล้ว tag `vX.Y.Z`
- [ ] ตรวจ Actions ว่า publish สำเร็จ
- [ ] แจ้งทีมใน Slack/Teams ถ้าเป็น breaking change
