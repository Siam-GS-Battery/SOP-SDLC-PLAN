# 5.5 การตรวจสอบหลัง Deploy — Post-Deploy Verification

## วัตถุประสงค์

เอกสารนี้รวบรวมวิธีการตรวจสอบหลังจาก Deploy เสร็จสิ้น เพื่อให้มั่นใจว่าระบบทำงานได้ถูกต้อง รวมถึงการจัดการ Redeploy และ Rollback

---

## 1. ตรวจสอบ Health Check

### 1.1 Backend Health Check

#### ใช้ Browser

1. เปิด Browser
2. ไปที่ `https://your-backend.up.railway.app/api/health`
3. ควรเห็น JSON response:

```json
{
  "status": "ok",
  "timestamp": "2025-12-15T10:30:00.000Z"
}
```

#### ใช้ Command Line (curl)

```bash
curl https://your-backend.up.railway.app/api/health
```

#### ใช้ PowerShell (Windows)

```powershell
Invoke-RestMethod -Uri "https://your-backend.up.railway.app/api/health"
```

### 1.2 Frontend Health Check

1. เปิด Browser
2. ไปที่ `https://your-frontend.up.railway.app/`
3. ควรเห็นหน้าแอปพลิเคชัน

```
┌─────────────────────────────────────────────────────────┐
│  🌐 https://your-frontend.up.railway.app               │
├─────────────────────────────────────────────────────────┤
│                                                          │
│  ┌───────────────────────────────────────────────────┐  │
│  │                                                   │  │
│  │            Kaizen Web Application                 │  │
│  │                                                   │  │
│  │            [Login Button]                         │  │
│  │                                                   │  │
│  └───────────────────────────────────────────────────┘  │
│                                                          │
│  ✅ หน้าเว็บแสดงผลถูกต้อง                               │
│                                                          │
└─────────────────────────────────────────────────────────┘
```

### 1.3 สรุปผลการตรวจสอบ Health Check

| Endpoint | Status ที่คาดหวัง | ผลลัพธ์ |
|----------|------------------|---------|
| Backend `/api/health` | `{"status": "ok"}` | ☐ ผ่าน |
| Frontend `/` | แสดงหน้าเว็บ | ☐ ผ่าน |

## 2. ตรวจสอบ Logs

### 2.1 วิธีดู Logs บน Railway

1. ไปที่ Railway Dashboard
2. คลิกที่ Service ที่ต้องการตรวจสอบ
3. ไปที่แท็บ **"Logs"**

```
┌─────────────────────────────────────────────────────────┐
│  Logs - Backend Service                                  │
├─────────────────────────────────────────────────────────┤
│                                                          │
│  10:30:00 [INFO]  Server started on port 5001           │
│  10:30:01 [INFO]  Connected to Supabase                 │
│  10:30:02 [INFO]  WebSocket server initialized          │
│  10:31:15 [INFO]  GET /api/health - 200                 │
│  10:32:30 [INFO]  POST /api/auth/login - 200            │
│                                                          │
│  [Filter: All] [Level: All ▼] [Search: _______]        │
│                                                          │
└─────────────────────────────────────────────────────────┘
```

### 2.2 วิธีอ่าน Logs

| Log Level | ความหมาย | ตัวอย่าง | ต้องทำอะไร |
|-----------|----------|----------|------------|
| `INFO` | ข้อมูลทั่วไป | Server started | ไม่ต้องทำอะไร |
| `WARN` | คำเตือน | Deprecated API | ควรตรวจสอบ |
| `ERROR` | ข้อผิดพลาด | Database connection failed | ต้องแก้ไข! |
| `DEBUG` | ข้อมูลสำหรับ Debug | Request payload | ใช้ตอน Debug |

### 2.3 Log Patterns ที่บ่งบอกปัญหา

#### ปัญหา Database

```
[ERROR] Error: connect ECONNREFUSED 127.0.0.1:5432
[ERROR] Error: Connection terminated unexpectedly
```

**วิธีแก้:** ตรวจสอบ Supabase credentials

#### ปัญหา CORS

```
[WARN] CORS blocked request from https://unknown-origin.com
```

**วิธีแก้:** ตรวจสอบ FRONTEND_URL

#### ปัญหา Memory

```
[ERROR] FATAL ERROR: CALL_AND_RETRY_LAST Allocation failed
[ERROR] JavaScript heap out of memory
```

**วิธีแก้:** Optimize code หรือเพิ่ม memory

| Metric | ค่าปกติ | ค่าที่ควรระวัง | ต้องทำอะไร |
|--------|--------|---------------|------------|
| CPU Usage | < 50% | > 80% | Optimize code |
| Memory Usage | < 500MB | > 1GB | ตรวจสอบ memory leaks |
| Response Time | < 200ms | > 1000ms | Optimize queries |
| Error Rate | 0% | > 1% | ตรวจสอบ logs |

## 4. ทดสอบฟีเจอร์หลัก

### 4.1 Checklist การทดสอบ

#### Basic Functions

| ฟีเจอร์ | วิธีทดสอบ | ผลลัพธ์ |
|---------|----------|---------|
| เข้าหน้าแรก | เปิด URL | ☐ ผ่าน |

| Console ไม่มี errors | เปิด DevTools → Console | ☐ ผ่าน |

#### Authentication

| ฟีเจอร์ | วิธีทดสอบ | ผลลัพธ์ |
|---------|----------|---------|
| Login | กรอก username/password | ☐ ผ่าน |

| ฟีเจอร์ | วิธีทดสอบ | ผลลัพธ์ |

## 5. การ Redeploy

### 5.1 Automatic Deployment

Railway จะ auto-deploy เมื่อ:
- Push code ไปยัง GitHub branch ที่เชื่อมต่อ
- เปลี่ยน Environment Variables

```
┌─────────────────────────────────────────────────────────┐
│  Automatic Deploy Flow                                   │
├─────────────────────────────────────────────────────────┤
│                                                          │
│    ┌──────────┐      ┌──────────┐      ┌──────────┐    │
│    │   Push   │ ───▶ │  Detect  │ ───▶ │  Build   │    │
│    │  to Git  │      │  Change  │      │          │    │
│    └──────────┘      └──────────┘      └──────────┘    │
│                                               │         │
│                                               ▼         │
│    ┌──────────┐      ┌──────────┐      ┌──────────┐    │
│    │   Live   │ ◀─── │  Switch  │ ◀─── │  Deploy  │    │
│    │          │      │  Traffic │      │          │    │
│    └──────────┘      └──────────┘      └──────────┘    │
│                                                          │
└─────────────────────────────────────────────────────────┘
```

### 5.2 ปิด Auto-Deploy (ถ้าต้องการ)

1. ไปที่ Service → **"Settings"**
2. หา **"Deployments"** section
3. Toggle off **"Auto Deploy"**

### 5.3 Manual Deployment

เมื่อต้องการ Deploy ด้วยตัวเอง:

1. ไปที่ Service
2. คลิกแท็บ **"Deployments"**
3. คลิก **"Deploy"** → **"Deploy Now"**

## 6. การ Rollback

### 6.1 เมื่อไหร่ควร Rollback?

- Deploy แล้วแอปพัง
- มี critical bugs
- Performance แย่ลงมาก
- ต้องการกลับไปเวอร์ชันเดิมด่วน

### 6.2 วิธี Rollback

1. ไปที่แท็บ **"Deployments"**
2. เลื่อนลงดู Deployment history
3. หา Deployment ที่ต้องการ (ที่ทำงานได้ดี)
4. คลิก **"..."** → **"Rollback"**

```
┌─────────────────────────────────────────────────────────┐
│  Deployment History                                      │
├─────────────────────────────────────────────────────────┤
│                                                          │
│  ┌─────────────────────────────────────────────────┐    │
│  │  ● Current                          10:30 AM    │    │
│  │    Deployed from main (abc1234)                 │    │
│  │    ❌ มีปัญหา                                    │    │
│  └─────────────────────────────────────────────────┘    │
│                                                          │
│  ┌─────────────────────────────────────────────────┐    │
│  │  ○ Previous                          9:00 AM    │    │
│  │    Deployed from main (def5678)     [...]       │    │
│  │    ✅ ทำงานได้ปกติ                    ├─────────┤    │
│  │                                      │ Rollback│    │
│  │                                      │ View    │    │
│  │                                      └─────────┘    │
│  └─────────────────────────────────────────────────┘    │
│                                                          │
└─────────────────────────────────────────────────────────┘
```

### 6.3 ข้อควรระวังเรื่อง Rollback

| ⚠️ ข้อควรระวัง | คำอธิบาย |
|---------------|----------|
| Environment Variables | Rollback จะใช้ค่า Variables ปัจจุบัน ไม่ใช่ค่าเดิม |
| Database Schema | ถ้า migrate database แล้ว Rollback อาจมีปัญหา |
| Breaking Changes | ถ้า API เปลี่ยน Frontend/Backend อาจไม่ compatible |

> **💡 Tip:** ก่อน Rollback ควรตรวจสอบว่า:
> - Environment Variables ยังใช้ได้กับเวอร์ชันเดิม
> - Database schema compatible กับเวอร์ชันเดิม

## 7. Deploy จาก Branch อื่น

### 7.1 วิธีเปลี่ยน Branch

1. ไปที่ Service Settings → **"Source"**
2. คลิก **"Change"** ที่ Branch
3. เลือก Branch ที่ต้องการ
4. Railway จะ Redeploy จาก branch ใหม่

### 7.2 Branch Strategy ที่แนะนำ

```
┌─────────────────────────────────────────────────────────┐
│  Branch Strategy                                         │
├─────────────────────────────────────────────────────────┤
│                                                          │
│  main ─────────────────────────────▶ Production         │
│    │                                                     │
│    └─── staging ───────────────────▶ Staging/Testing    │
│           │                                              │
│           └─── develop ────────────▶ Development        │
│                  │                                       │
│                  ├─── feature/xxx                        │
│                  └─── bugfix/xxx                         │
│                                                          │
└─────────────────────────────────────────────────────────┘
```

| Branch | Environment | ใช้ทำอะไร |
|--------|-------------|----------|
| `main` | Production | Live สำหรับผู้ใช้จริง |
| `staging` | Staging | ทดสอบก่อน Production |
| `develop` | Development | พัฒนาและทดสอบ |

## 8. Checklist หลัง Deploy

### 8.1 ตรวจสอบทันที

- [ ] Health Check ผ่านทั้ง Backend และ Frontend
- [ ] ไม่มี ERROR ใน Logs
- [ ] Metrics อยู่ในเกณฑ์ปกติ
- [ ] หน้าเว็บแสดงผลถูกต้อง

### 8.2 ทดสอบ Functions

- [ ] Login/Logout ทำงานได้
- [ ] CRUD operations ทำงานได้
- [ ] File upload ทำงานได้ (ถ้ามี)
- [ ] WebSocket เชื่อมต่อได้ (ถ้ามี)

### 8.3 ตรวจสอบ Performance

- [ ] Page load time < 3 วินาที
- [ ] API response time < 500ms
- [ ] ไม่มี memory leaks
