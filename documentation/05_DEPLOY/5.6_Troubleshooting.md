## ปัญหาที่ 1: Build Failed

### อาการ

```
┌─────────────────────────────────────────────────────────┐
│  Deployment Status: Failed                               │
├─────────────────────────────────────────────────────────┤
│                                                          │
│  ❌ Build failed                                         │
│                                                          │
│  Error: TypeScript compilation failed                    │
│  Error: Cannot find module 'xxx'                         │
│  Error: npm ERR! code ELIFECYCLE                        │
│                                                          │
└─────────────────────────────────────────────────────────┘
```

### สาเหตุและวิธีแก้ไข

#### สาเหตุ 1: TypeScript Compilation Errors

**ตรวจสอบ:**
```bash
cd backend
npx tsc --noEmit
```

**วิธีแก้ไข:**
1. แก้ไข TypeScript errors ทั้งหมด
2. ถ้ามี errors จาก node_modules:
   ```json
   // tsconfig.json
   {
     "compilerOptions": {
       "skipLibCheck": true
     }
   }
   ```

#### สาเหตุ 2: Missing Dependencies

**ตรวจสอบ:**
- ดู error message ใน Build logs
- มักเป็น `Cannot find module 'xxx'`

**วิธีแก้ไข:**
```bash
# ติดตั้ง dependency ที่หายไป
npm install xxx

# หรือถ้าเป็น TypeScript types
npm install -D @types/xxx
```

#### สาเหตุ 3: TypeScript อยู่ใน devDependencies

**ตรวจสอบ:**
```json
// package.json
{
  "devDependencies": {
    "typescript": "^5.0.0"  // ❌ ผิด!
  }
}
```

**วิธีแก้ไข:**
```json
// package.json
{
  "dependencies": {
    "typescript": "^5.0.0"  // ✅ ถูก!
  }
}
```

> **💡 Tip:** Railway ติดตั้งเฉพาะ `dependencies` ใน production mode

#### สาเหตุ 4: Build Script ไม่ถูกต้อง

**ตรวจสอบ:**
```json
// package.json
{
  "scripts": {
    "build": "tsc"  // ต้องมี
  }
}
```

### Checklist แก้ไข Build Failed

- [ ] รัน `npm run build` ใน Local ผ่าน
- [ ] ไม่มี TypeScript errors
- [ ] `typescript` อยู่ใน dependencies
- [ ] Dependencies ครบทุกตัว
- [ ] `skipLibCheck: true` ใน tsconfig.json

## ปัญหาที่ 2: CORS Error

### อาการ

```
Access to XMLHttpRequest at 'https://backend-xxx.up.railway.app/api/users'
from origin 'https://frontend-yyy.up.railway.app' has been blocked by
CORS policy: No 'Access-Control-Allow-Origin' header is present on the
requested resource.
```

### สาเหตุและวิธีแก้ไข

#### สาเหตุ 1: FRONTEND_URL ไม่ถูกต้อง

**ตรวจสอบ:**
```env
# Backend Variables
FRONTEND_URL=https://frontend-xxx.up.railway.app
```

**วิธีแก้ไข:**
1. ไปที่ Backend Service → Variables
2. ตรวจสอบ/แก้ไข `FRONTEND_URL`
3. **ต้องไม่มี `/` ต่อท้าย!**
   ```env
   # ❌ ผิด
   FRONTEND_URL=https://frontend-xxx.up.railway.app/

   # ✅ ถูก
   FRONTEND_URL=https://frontend-xxx.up.railway.app
   ```
4. Railway จะ Redeploy อัตโนมัติ

#### สาเหตุ 2: CORS Middleware ไม่ถูกต้อง

**ตรวจสอบ Code:**
```typescript
// src/server.ts หรือ src/app.ts
import cors from 'cors';

app.use(cors({
  origin: process.env.FRONTEND_URL,
  credentials: true
}));
```

**วิธีแก้ไข:**
```typescript
// ถ้าต้องการอนุญาตหลาย origins
const allowedOrigins = [
  process.env.FRONTEND_URL,
  'http://localhost:3000'  // สำหรับ development
].filter(Boolean);

app.use(cors({
  origin: (origin, callback) => {
    if (!origin || allowedOrigins.includes(origin)) {
      callback(null, true);
    } else {
      callback(new Error('Not allowed by CORS'));
    }
  },
  credentials: true
}));
```

#### สาเหตุ 3: ลืม Redeploy Backend

**วิธีแก้ไข:**
1. หลังแก้ไข `FRONTEND_URL`
2. ไปที่ Backend → Deployments
3. คลิก Deploy → Deploy Now

### Checklist แก้ไข CORS

- [ ] `FRONTEND_URL` ตรงกับ URL จริงของ Frontend
- [ ] ไม่มี `/` ต่อท้าย URL
- [ ] CORS middleware ตั้งค่าถูกต้อง
- [ ] Redeploy Backend หลังแก้ไข Variables

## ปัญหาที่ 3: Database Connection Failed

### อาการ

```
Error: connect ECONNREFUSED 127.0.0.1:5432
Error: Connection terminated unexpectedly
Error: FATAL: password authentication failed for user "xxx"
```

### สาเหตุและวิธีแก้ไข

#### สาเหตุ 1: Supabase Credentials ไม่ถูกต้อง

**ตรวจสอบ:**
```env
SUPABASE_URL=https://xxxxxxxxxxxxx.supabase.co
SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIs...
SUPABASE_SERVICE_KEY=eyJhbGciOiJIUzI1NiIs...
```

**วิธีแก้ไข:**
1. ไปที่ Supabase Dashboard → Settings → API
2. Copy ค่าใหม่
3. อัปเดตใน Railway Variables

#### สาเหตุ 2: Supabase Project ถูก Pause

**ตรวจสอบ:**
1. ไปที่ Supabase Dashboard
2. ดูว่า Project status เป็น "Active" หรือไม่

**วิธีแก้ไข:**
1. ถ้า Project ถูก pause → คลิก "Restore"
2. รอ 1-2 นาที
3. Redeploy Backend

#### สาเหตุ 3: ใช้ Connection String ผิดรูปแบบ

**รูปแบบที่ถูกต้อง:**
```env
# สำหรับ Supabase JS Client
SUPABASE_URL=https://xxxxx.supabase.co
SUPABASE_ANON_KEY=eyJ...

# สำหรับ Direct Connection (ถ้าใช้)
DATABASE_URL=postgresql://postgres:[password]@db.xxxxx.supabase.co:5432/postgres
```

### ทดสอบ Connection

```bash
# ทดสอบว่า Supabase URL เข้าถึงได้
curl https://your-supabase-url.supabase.co/rest/v1/ \
  -H "apikey: your-anon-key"

# ควรได้ response 200 หรือ empty array []
```

### Checklist แก้ไข Database Connection

- [ ] `SUPABASE_URL` ถูกต้อง
- [ ] `SUPABASE_ANON_KEY` ถูกต้อง
- [ ] `SUPABASE_SERVICE_KEY` ถูกต้อง
- [ ] Supabase Project ไม่ถูก pause
- [ ] ทดสอบ connection ด้วย curl ผ่าน

## ปัญหาที่ 4: WebSocket ไม่ทำงาน

### อาการ

```
WebSocket connection to 'wss://backend-xxx.up.railway.app/socket.io/...'
failed: Connection closed before receiving a handshake response
```

### สาเหตุและวิธีแก้ไข

#### สาเหตุ 1: URL ไม่ถูกต้อง

**ตรวจสอบ:**
```env
# Frontend Variables
REACT_APP_WEBSOCKET_URL=https://backend-xxx.up.railway.app
```

**วิธีแก้ไข:**
```env
# ❌ ผิด - ใช้ http
REACT_APP_WEBSOCKET_URL=http://backend-xxx.up.railway.app

# ❌ ผิด - มี path ต่อท้าย
REACT_APP_WEBSOCKET_URL=https://backend-xxx.up.railway.app/ws

# ✅ ถูก - ใช้ https และไม่มี path
REACT_APP_WEBSOCKET_URL=https://backend-xxx.up.railway.app
```

#### สาเหตุ 2: CORS สำหรับ WebSocket ไม่ถูกต้อง

**ตรวจสอบ Backend Code:**
```typescript
import { Server } from 'socket.io';

const io = new Server(server, {
  cors: {
    origin: process.env.FRONTEND_URL,
    credentials: true
  }
});
```

#### สาเหตุ 3: Frontend Connection Config ไม่ถูกต้อง

**ตรวจสอบ Frontend Code:**
```typescript
import { io } from 'socket.io-client';

// ✅ ถูกต้อง
const socket = io(process.env.REACT_APP_WEBSOCKET_URL, {
  withCredentials: true,
  transports: ['websocket', 'polling']
});

// ❌ ผิด - ไม่ได้ใส่ options
const socket = io(process.env.REACT_APP_WEBSOCKET_URL);
```

### Checklist แก้ไข WebSocket

- [ ] `REACT_APP_WEBSOCKET_URL` ใช้ `https://`
- [ ] ไม่มี path ต่อท้าย URL
- [ ] Backend CORS อนุญาต Frontend origin
- [ ] Frontend ใช้ `withCredentials: true`

## ปัญหาที่ 5: Service Keeps Restarting

### อาการ

```
┌─────────────────────────────────────────────────────────┐
│  Deployments                                             │
├─────────────────────────────────────────────────────────┤
│  ● Crashed               10:30:00                        │
│  ● Crashed               10:28:00                        │
│  ● Crashed               10:26:00                        │
│  ● Crashed               10:24:00                        │
└─────────────────────────────────────────────────────────┘
```

### สาเหตุและวิธีแก้ไข

#### สาเหตุ 1: Unhandled Errors

**ตรวจสอบ Logs:**
```
Error: Cannot read property 'xxx' of undefined
UnhandledPromiseRejection: ...
```

**วิธีแก้ไข:**
```typescript
// เพิ่ม global error handlers
process.on('uncaughtException', (error) => {
  console.error('Uncaught Exception:', error);
  // Log error แต่ไม่ crash
});

process.on('unhandledRejection', (reason, promise) => {
  console.error('Unhandled Rejection at:', promise, 'reason:', reason);
});
```

#### สาเหตุ 2: Memory Leak

**ตรวจสอบ Metrics:**
- Memory เพิ่มขึ้นเรื่อยๆ จนถึง limit
- แล้ว crash

**วิธีแก้ไข:**
1. ตรวจสอบ code ที่มี memory leak:
   - Event listeners ที่ไม่ได้ remove
   - Arrays/Objects ที่โตขึ้นเรื่อยๆ
   - Cached data ที่ไม่ได้ clear

2. เพิ่ม memory limit (ถ้าจำเป็น):
   ```toml
   # railway.toml
   [deploy]
   memory = "512Mi"
   ```

#### สาเหตุ 3: Health Check Failed

**ตรวจสอบ:**
- Health check endpoint ทำงานช้าเกินไป
- Health check endpoint มี error

**วิธีแก้ไข:**
1. ตรวจสอบว่า `/api/health` ตอบกลับเร็ว (< 5 วินาที)
2. เพิ่ม timeout ใน railway.toml:
   ```toml
   [deploy]
   healthcheckTimeout = 300
   ```

### Checklist แก้ไข Restart Loop

- [ ] ตรวจสอบ Logs หา error
- [ ] เพิ่ม global error handlers
- [ ] ตรวจสอบ memory usage
- [ ] Health check endpoint ทำงานเร็ว

## ปัญหาที่ 6: Environment Variables ไม่ทำงาน

### อาการ

```typescript
console.log(process.env.MY_VARIABLE); // undefined
```

### สาเหตุและวิธีแก้ไข

#### สาเหตุ 1: ชื่อตัวแปรไม่ถูกต้อง

**วิธีแก้ไข:**
```env
# ❌ ผิด - มีช่องว่าง
MY VARIABLE=value

# ❌ ผิด - มี special characters
MY-VARIABLE=value

# ✅ ถูก - ใช้ underscore
MY_VARIABLE=value
```

#### สาเหตุ 2: Frontend ไม่ได้ขึ้นต้นด้วย REACT_APP_

**วิธีแก้ไข:**
```env
# ❌ ผิด - Frontend จะไม่เห็น
API_URL=https://...

# ✅ ถูก - Frontend จะเห็น
REACT_APP_API_URL=https://...
```

> **⚠️ สำคัญ:** Create React App จะไม่ expose variables ที่ไม่ได้ขึ้นต้นด้วย `REACT_APP_`

#### สาเหตุ 3: ยังไม่ได้ Redeploy

**วิธีแก้ไข:**
1. หลังเปลี่ยน Variables ต้อง Redeploy
2. Railway มักจะ auto-redeploy แต่บางครั้งต้องทำ manual

#### สาเหตุ 4: Backend ไม่ได้ใช้ dotenv

**ตรวจสอบ Backend Code:**
```typescript
// ต้องมีบรรทัดนี้ที่ต้นไฟล์
import dotenv from 'dotenv';
dotenv.config();

// แล้วค่อยใช้ process.env
const port = process.env.PORT;
```

### Checklist แก้ไข Environment Variables

- [ ] ชื่อตัวแปรไม่มีช่องว่างหรือ special characters
- [ ] Frontend variables ขึ้นต้นด้วย `REACT_APP_`
- [ ] Redeploy หลังเปลี่ยน Variables
- [ ] Backend import dotenv ถูกต้อง

## ปัญหาที่ 7: 404 Not Found

### อาการ

```
404 Not Found

nginx/1.x.x
```

### สาเหตุและวิธีแก้ไข

#### สาเหตุ 1: Frontend SPA Routing

**อาการ:** Refresh หน้าที่ไม่ใช่หน้าแรกแล้วได้ 404

**วิธีแก้ไข:**
```toml
# frontend/railway.toml
[deploy]
startCommand = "npx serve -s build -l $PORT"
```

> **💡 Tip:** `-s` flag บอก serve ให้ redirect ทุก routes ไปที่ index.html

#### สาเหตุ 2: API Route ไม่ถูกต้อง

**ตรวจสอบ:**
```env
# ❌ ผิด - ไม่มี /api
REACT_APP_API_BASE_URL=https://backend.up.railway.app

# ✅ ถูก - มี /api
REACT_APP_API_BASE_URL=https://backend.up.railway.app/api
```

#### สาเหตุ 3: Root Directory ไม่ถูกต้อง

**ตรวจสอบ Railway Settings:**
- Backend: Root Directory = `backend`
- Frontend: Root Directory = `frontend`

### Checklist แก้ไข 404

- [ ] Frontend ใช้ `serve -s`
- [ ] API URL มี `/api` ต่อท้าย (ถ้า Backend ใช้ prefix)
- [ ] Root Directory ตั้งค่าถูกต้อง

## ปัญหาที่ 8: Slow Performance

### อาการ

- หน้าเว็บโหลดช้า (> 3 วินาที)
- API ตอบกลับช้า (> 500ms)
- High CPU/Memory usage

### สาเหตุและวิธีแก้ไข

#### สาเหตุ 1: Cold Start

**อธิบาย:** Railway จะ sleep service ที่ไม่มีการใช้งาน ทำให้ request แรกช้า

**วิธีแก้ไข:**
- ใช้ health check ping ทุก 5 นาที
- หรือยอมรับ cold start (ประหยัดค่าใช้จ่าย)

#### สาเหตุ 2: Database Queries ช้า

**วิธีแก้ไข:**
1. เพิ่ม indexes ใน database
2. ใช้ pagination
3. Cache ข้อมูลที่ใช้บ่อย

#### สาเหตุ 3: ไม่มี Compression

**วิธีแก้ไข Backend:**
```typescript
import compression from 'compression';
app.use(compression());
```

#### สาเหตุ 4: Frontend Bundle ใหญ่เกินไป

**วิธีแก้ไข:**
1. ใช้ code splitting
2. Lazy load components
3. Optimize images

### Checklist แก้ไข Performance

- [ ] ตรวจสอบ cold start time
- [ ] Database queries มี indexes
- [ ] Backend ใช้ compression
- [ ] Frontend bundle size < 500KB
