# การทดสอบระบบจากผู้ใช้งาน (User Acceptance Test - UAT)

User Acceptance Test คือกระบวนการทดสอบระบบขั้นตอนสุดท้ายเพื่อให้แน่ใจว่า ระบบที่พัฒนาพร้อมที่จะใช้งานได้จริง ตรงตามกระบวนการทางธุรกิจ (Business Process) และความต้องการของผู้ใช้งาน ที่ได้กำหนดไว้ (Software Requirements) โดยผลลัพธ์การทดสอบ จะต้องเป็นไปตามเงื่อนไข ความสมบูรณ์ของระบบที่ควรจะเป็น และสามารถยอมรับได้ (Acceptance Criteria) ซึ่งทีมพัฒนาระบบรวมถึงส่วนงานอื่นๆ ที่เกี่ยวข้องได้จัดทำ เอกสารสำรวบนับขึ้นเพื่อเป็นเครื่องมือ ในการทดสอบระบบร่วมกันและได้แบ่งการทดสอบออกเป็นฟังก์ชันงานดังต่อไปนี้

## คำแนะนำการใช้งาน Template

### 1. การตั้งชื่อ Test Case
- ใช้รูปแบบ: `UAT-[MODULE]-[NUMBER]`
- ตัวอย่าง: `UAT-WEB-01`, `UAT-API-01`, `UAT-AUTH-01`

### 2. การกำหนด Test Priority
- **High**: ฟังก์ชันหลักที่สำคัญต่อระบบ (Core Functions)
- **Medium**: ฟังก์ชันรองที่ใช้งานบ่อย (Common Functions)
- **Low**: ฟังก์ชันเสริมหรือใช้งานน้อย (Optional Functions)

### 3. การเขียน Test Steps ที่ดี
- เขียนให้ชัดเจน เฉพาะเจาะจง และสามารถทำซ้ำได้
- ระบุ Test Data ที่ใช้ในแต่ละขั้นตอน
- ระบุผลลัพธ์ที่คาดหวังอย่างชัดเจน
- ครอบคลุมทั้ง Happy Path และ Error Cases

### 4. การบันทึกผลการทดสอบ
- **Pass**: ทดสอบผ่าน ผลลัพธ์ตรงตามที่คาดหวัง
- **Fail**: ทดสอบไม่ผ่าน ผลลัพธ์ไม่ตรงตามที่คาดหวัง
- บันทึกหมายเหตุและ Screenshot (ถ้ามี) เมื่อเกิด Fail

### 5. Best Practices
- ทดสอบในสภาพแวดล้อมที่เหมือนกับ Production
- ใช้ข้อมูลจริงหรือข้อมูลที่ใกล้เคียงกับการใช้งานจริง
- ทดสอบทุก Browser และ Device ที่ระบบรองรับ
- บันทึกปัญหาและข้อเสนอแนะอย่างละเอียด
