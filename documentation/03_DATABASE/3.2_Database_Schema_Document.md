# 3.2 Database Schema Document

## วิธีการเขียน
Database Schema Document คือเอกสารที่อธิบายโครงสร้างฐานข้อมูลโดยละเอียด รวมถึง tables, columns, data types, constraints, indexes, และความสัมพันธ์ระหว่างตาราง

---

## วัตถุประสงค์

Database Schema Document ช่วยให้:
1. **Developer เข้าใจโครงสร้าง** - รู้ว่าแต่ละตารางเก็บข้อมูลอะไร
2. **ทีมทำงานร่วมกัน** - มีเอกสารอ้างอิงเดียวกัน
3. **Onboard Developer ใหม่ง่าย** - ทำความเข้าใจ schema ได้เร็ว
4. **วางแผน Migration** - ติดตามการเปลี่ยนแปลง schema
5. **Optimize Performance** - วางแผน indexes และ queries
6. **Maintain Data Integrity** - กำหนด constraints ชัดเจน

### 1. users

**คำอธิบาย**: เก็บข้อมูลผู้ใช้งานระบบ

**SQL Schema:**
```sql
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    email VARCHAR(255) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    first_name VARCHAR(100) NOT NULL,
    last_name VARCHAR(100) NOT NULL,
    phone VARCHAR(20),
    role VARCHAR(20) DEFAULT 'customer' CHECK (role IN ('customer', 'admin', 'vendor')),
    is_active BOOLEAN DEFAULT TRUE,
    email_verified_at TIMESTAMP,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Indexes
CREATE INDEX idx_users_email ON users(email);
CREATE INDEX idx_users_role ON users(role);
CREATE INDEX idx_users_created_at ON users(created_at DESC);

-- Triggers
CREATE TRIGGER update_users_updated_at
    BEFORE UPDATE ON users
    FOR EACH ROW
    EXECUTE FUNCTION update_updated_at_column();
```

**Data Dictionary:**

### 2. products

**คำอธิบาย**: เก็บข้อมูลสินค้า

**SQL Schema:**
```sql
CREATE TABLE products (
    id SERIAL PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    slug VARCHAR(255) UNIQUE NOT NULL,
    description TEXT,
    price DECIMAL(10, 2) NOT NULL CHECK (price >= 0),
    cost DECIMAL(10, 2) CHECK (cost >= 0),
    stock_quantity INTEGER DEFAULT 0 CHECK (stock_quantity >= 0),
    sku VARCHAR(100) UNIQUE NOT NULL,
    category_id INTEGER REFERENCES categories(id) ON DELETE SET NULL,
    vendor_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
    image_url TEXT,
    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Indexes
CREATE INDEX idx_products_slug ON products(slug);
CREATE INDEX idx_products_category_id ON products(category_id);
CREATE INDEX idx_products_vendor_id ON products(vendor_id);
CREATE INDEX idx_products_price ON products(price);
CREATE INDEX idx_products_created_at ON products(created_at DESC);
CREATE INDEX idx_products_name_search ON products USING gin(to_tsvector('english', name));

-- Triggers
CREATE TRIGGER update_products_updated_at
    BEFORE UPDATE ON products
    FOR EACH ROW
    EXECUTE FUNCTION update_updated_at_column();
```

    shipping_address TEXT NOT NULL,
    notes TEXT,

## Common Triggers & Functions

### 1. Update `updated_at` Trigger Function

```sql
CREATE OR REPLACE FUNCTION update_updated_at_column()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = CURRENT_TIMESTAMP;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

**ใช้กับตาราง**: users, products, categories, orders, carts, reviews

---

### 2. Update Product Stock After Order

```sql
CREATE OR REPLACE FUNCTION update_product_stock_after_order()
RETURNS TRIGGER AS $$
BEGIN
    UPDATE products
    SET stock_quantity = stock_quantity - NEW.quantity
    WHERE id = NEW.product_id;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER update_stock_on_order
    AFTER INSERT ON order_items
    FOR EACH ROW
    EXECUTE FUNCTION update_product_stock_after_order();
```

---

### 3. Auto-generate Order Number

```sql
CREATE OR REPLACE FUNCTION generate_order_number()
RETURNS TRIGGER AS $$
BEGIN
    NEW.order_number = 'ORD-' || TO_CHAR(CURRENT_DATE, 'YYYY') || '-' || LPAD(NEW.id::TEXT, 6, '0');
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER set_order_number
    BEFORE INSERT ON orders
    FOR EACH ROW
    EXECUTE FUNCTION generate_order_number();
```

## Indexes Strategy

### 1. Primary Key Indexes
- สร้างอัตโนมัติสำหรับ PRIMARY KEY
- ใช้สำหรับ lookups โดยตรง

### 2. Foreign Key Indexes
- สร้าง index บน FK columns ทั้งหมด
- เพิ่มความเร็ว JOIN queries

### 3. Unique Indexes
- email, slug, sku, order_number
- ป้องกันข้อมูลซ้ำ

### 4. Composite Indexes
- `(user_id, product_id)` ใน carts, reviews
- `(order_id, product_id)` ใน order_items
- ใช้สำหรับ queries ที่ filter หลาย columns

### 5. Full-Text Search Indexes
- `to_tsvector()` บน products.name
- รองรับการค้นหาสินค้า

### 6. Date/Time Indexes
- `created_at DESC` สำหรับการเรียงลำดับล่าสุด

## Constraints Summary

### Primary Keys
- ทุกตารางมี `id SERIAL PRIMARY KEY`

### Foreign Keys
- `products.category_id` → `categories.id`
- `products.vendor_id` → `users.id`
- `orders.user_id` → `users.id`
- `order_items.order_id` → `orders.id`
- `order_items.product_id` → `products.id`
- `carts.user_id` → `users.id`
- `carts.product_id` → `products.id`
- `reviews.product_id` → `products.id`
- `reviews.user_id` → `users.id`
- `payment_logs.order_id` → `orders.id`

### Unique Constraints
- `users.email`
- `products.slug`, `products.sku`
- `categories.slug`
- `orders.order_number`
- `carts(user_id, product_id)`
- `reviews(product_id, user_id)`
- `payment_logs.transaction_id`

### Check Constraints
- `users.role IN ('customer', 'admin', 'vendor')`
- `products.price >= 0`
- `products.stock_quantity >= 0`
- `orders.status IN (...)`
- `orders.payment_status IN (...)`
- `order_items.quantity > 0`
- `reviews.rating >= 1 AND rating <= 5`

### Default Values
- Timestamps: `DEFAULT CURRENT_TIMESTAMP`
- Booleans: `DEFAULT TRUE` หรือ `DEFAULT FALSE`
- Integers: `DEFAULT 0`

## Performance Optimization Tips

### 1. Use Indexes Wisely
```sql
-- ดี: Index บน FK และ columns ที่ใช้ WHERE/ORDER BY บ่อย
CREATE INDEX idx_products_category_id ON products(category_id);

-- ไม่ดี: Index บน column ที่ไม่ค่อยใช้
-- CREATE INDEX idx_products_description ON products(description);
```

### 2. Avoid SELECT *
```sql
-- ดี: เลือกแค่ columns ที่ต้องการ
SELECT id, name, price FROM products WHERE category_id = 5;

-- ไม่ดี: เลือกทุก column
-- SELECT * FROM products WHERE category_id = 5;
```

### 3. Use LIMIT for Pagination
```sql
-- ดี: Paginate results
SELECT * FROM products ORDER BY created_at DESC LIMIT 20 OFFSET 0;

-- ไม่ดี: Load ทุกแถว
-- SELECT * FROM products ORDER BY created_at DESC;
```

### 4. Optimize Joins
```sql
-- ดี: ใช้ INNER JOIN เมื่อต้องการแค่ matching rows
SELECT p.name, c.name as category
FROM products p
INNER JOIN categories c ON p.category_id = c.id;

-- ดี: ใช้ LEFT JOIN เมื่อต้องการ products ทั้งหมด (รวม products ที่ไม่มี category)
SELECT p.name, c.name as category
FROM products p
LEFT JOIN categories c ON p.category_id = c.id;
```

### 5. Use Connection Pooling
- ใช้ connection pooling (pg-pool, Sequelize, Prisma)
- จำกัดจำนวน connections (default: 10-20)

### 6. Cache Frequent Queries
- ใช้ Redis cache สำหรับ queries ที่ถูกเรียกบ่อย
- Set TTL (Time To Live) ที่เหมาะสม

## Database Access Patterns

### 1. Read Products List (with Category)
```sql
SELECT p.id, p.name, p.slug, p.price, p.stock_quantity, c.name as category_name
FROM products p
LEFT JOIN categories c ON p.category_id = c.id
WHERE p.is_active = TRUE
ORDER BY p.created_at DESC
LIMIT 20 OFFSET 0;
```

### 2. Get User Orders (with Items)
```sql
SELECT
    o.id, o.order_number, o.status, o.total, o.created_at,
    json_agg(json_build_object(
        'product_name', p.name,
        'quantity', oi.quantity,
        'price', oi.price,
        'subtotal', oi.subtotal
    )) as items
FROM orders o
INNER JOIN order_items oi ON o.id = oi.order_id
INNER JOIN products p ON oi.product_id = p.id
WHERE o.user_id = 25
GROUP BY o.id
ORDER BY o.created_at DESC;
```

### 3. Get Product with Reviews
```sql
SELECT
    p.id, p.name, p.description, p.price,
    COALESCE(AVG(r.rating), 0) as avg_rating,
    COUNT(r.id) as review_count
FROM products p
LEFT JOIN reviews r ON p.id = r.product_id AND r.is_approved = TRUE
WHERE p.id = 101
GROUP BY p.id;
```

### 4. Full-Text Search Products
```sql
SELECT id, name, description, price
FROM products
WHERE to_tsvector('english', name || ' ' || COALESCE(description, '')) @@ plainto_tsquery('english', 'iPhone 15')
ORDER BY price ASC
LIMIT 10;
```

## Security Best Practices

### 1. Use Parameterized Queries
```javascript
// ดี: Parameterized query (prevents SQL injection)
const result = await db.query('SELECT * FROM users WHERE email = $1', [email]);

// ไม่ดี: String concatenation (vulnerable to SQL injection)
// const result = await db.query(`SELECT * FROM users WHERE email = '${email}'`);
```

### 2. Hash Passwords
```javascript
const bcrypt = require('bcrypt');
const saltRounds = 10;

// Hash password
const passwordHash = await bcrypt.hash(plainPassword, saltRounds);

// Verify password
const isMatch = await bcrypt.compare(plainPassword, passwordHash);
```

### 3. Use Environment Variables
```bash
# .env
DATABASE_URL=postgresql://username:password@localhost:5432/ecommerce_db
DATABASE_SSL=true
DATABASE_POOL_SIZE=20
```

### 4. Implement Row-Level Security (RLS)
```sql
-- Enable RLS
ALTER TABLE products ENABLE ROW LEVEL SECURITY;

-- Policy: Users can only see active products
CREATE POLICY products_select_policy ON products
    FOR SELECT
    USING (is_active = TRUE);

-- Policy: Only vendors can update their own products
CREATE POLICY products_update_policy ON products
    FOR UPDATE
    USING (vendor_id = current_user_id());
```

### 5. Limit Database User Permissions
```sql
-- Create app user with limited permissions
CREATE USER app_user WITH PASSWORD 'secure_password';

-- Grant only necessary permissions
GRANT CONNECT ON DATABASE ecommerce_db TO app_user;
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO app_user;
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO app_user;

-- Revoke dangerous permissions
REVOKE CREATE ON SCHEMA public FROM app_user;
```
