## โครงสร้าง Asana ของทีม

### Board Structure

ทีมใช้ Asana แบ่งงานเป็น 3 ระดับ:

```
Asana Workspace
├── 📋 Quarterly Roadmap (Portfolio)     ← เป้าหมายรายไตรมาส
│   ├── Q1: Foundation
│   ├── Q2: Stabilize & Cadence
│   ├── Q3: Automate Delivery
│   └── Q4: Optimize & Scale
│
├── 📋 Kaizen - Sprint Board (Project)   ← งาน Sprint ปัจจุบัน
│   ├── Backlog
│   ├── To Do (Sprint นี้)
│   ├── In Progress
│   ├── In Review
│   └── Done
│
└── 📋 FixAsset - Sprint Board (Project) ← งาน Sprint ปัจจุบัน
```

### วิธีเชื่อม Task กับ Roadmap

ทุก Task ใน Sprint Board ควรลิงก์กลับไปยัง Quarterly Roadmap:

```
Quarterly Roadmap → Milestone → Sprint Task → Branch → PR → Release
```

**ตัวอย่าง:**
- Roadmap: `Q1 - Foundation > Standardize > Define DoR/DoD`
- Sprint Task: `สร้าง PR Checklist Template`
- Branch: `feature/1234567890-pr-checklist-template`
- PR: `feat(workflow): add PR checklist template`

## วิธีใช้ Asana ให้สอดคล้องกับ Roadmap

### Sprint Planning (ทุกวันจันทร์เช้า)

1. **ดู Quarterly Roadmap** — ไตรมาสนี้ต้องทำ milestone ไหน
2. **ดึง Task จาก Backlog** — เลือก task ที่ตอบโจทย์ milestone นั้น
3. **ย้ายเข้า Sprint** — ย้ายไป column "To Do (Sprint นี้)"
4. **Assign + Estimate** — กำหนดคนรับผิดชอบ + ประเมินเวลาร่วมกัน

### Daily Flow

```
ทุกเช้า: ดึง code ล่าสุดจาก staging
→ เปิด Asana ดู task ของตัวเอง
→ ย้าย task เป็น "In Progress"
→ สร้าง branch ตาม Asana Task ID
→ ทำงาน + commit ทุก 1-2 ชม.
→ เสร็จ → เปิด PR ลิงก์ Asana Task
→ ย้าย task เป็น "In Review"
```

### Sprint Review (ทุก 2 สัปดาห์)

1. **Demo** สิ่งที่ทำเสร็จใน Sprint
2. **เทียบกับ Roadmap** — ทำได้ตาม milestone ไหม
3. **ปรับแผน Sprint ถัดไป** — ถ้า milestone เลื่อนให้ปรับ priority

## Naming Convention ใน Asana

### Task Title

```
[Type] ชื่อ task สั้นกระชับ
```

**ตัวอย่าง:**
- `[Feature] สร้างหน้า Login`
- `[Bug] แก้ปัญหา null response ใน payment API`
- `[Chore] ตั้งค่า CI pipeline สำหรับ Kaizen repo`
- `[Docs] เขียน Runbook สำหรับ deploy/rollback`

### Task Description

ทุก Task ควรมี:

```markdown
## สิ่งที่ต้องทำ
- รายละเอียดงาน

## Acceptance Criteria
- [ ] เงื่อนไขที่ต้องผ่าน

## Linked to
- Roadmap Milestone: [ชื่อ milestone]
- Figma: [ลิงก์ ถ้ามี]
```

## การติดตามความคืบหน้า

### Weekly Check (ทุกวันศุกร์)

| สิ่งที่ดู | ดูที่ไหน |
|:---------|:---------|
| Task ที่ค้าง In Progress นานเกินไป | Asana Sprint Board |
| PR ที่รอ review เกิน 24 ชม. | GitHub Pull Requests |
| Milestone ไตรมาสนี้คืบหน้าแค่ไหน | Asana Quarterly Roadmap |

### Quarterly Review (ทุกสิ้นไตรมาส)

1. ทบทวน milestones ที่ทำได้/ไม่ได้
2. ปรับ Roadmap ไตรมาสถัดไปตามสถานการณ์จริง
3. บันทึก lessons learned
