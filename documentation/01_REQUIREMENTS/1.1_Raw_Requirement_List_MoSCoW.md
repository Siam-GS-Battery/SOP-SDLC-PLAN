# 1.1 Raw Requirement List (MoSCoW)

## วิธีการเขียน
เอกสารนี้ใช้จัดลำดับความสำคัญของ Requirements ตามแนวทาง MoSCoW

### MoSCoW Prioritization:
- **M** (Must have) - ต้องมี ขาดไม่ได้ (Critical for success)
- **S** (Should have) - ควรมี สำคัญรองลงมา (Important but not critical)
- **C** (Could have) - อาจมี ถ้ามีเวลาเหลือ (Nice to have)
- **W** (Won't have) - ไม่มีในเวอร์ชันนี้ (Not in this release)

## วิธีการเขียน Requirements

### โครงสร้างตาราง:
1. **ID**: รหัสอ้างอิง (REQ-XXX)
2. **Requirement**: ชื่อความต้องการ (สั้น กระชับ)
3. **Description**: รายละเอียดความต้องการ
4. **Priority (MoSCoW)**: ระดับความสำคัญ (Must/Should/Could/Won't Have)
5. **Category**: หมวดหมู่ (Security, UI/UX, Core Function, etc.)
6. **Stakeholder**: ผู้เกี่ยวข้อง/ผู้ร้องขอ
7. **Notes**: หมายเหตุเพิ่มเติม

### Tips การเขียน Requirements (SMART Criteria)

![Alt text](https://cdn2.hubspot.net/hubfs/2632255/smart%20goals%20marketing%20hubspot%20inbound%202.png "SMART Goals")

**SMART Requirements** - George T. Doran (1981):
1. **S - Specific (ชัดเจน)** - เขียนให้เข้าใจง่าย ไม่คลุมเครือ
2. **M - Measurable (วัดผลได้)** - กำหนดเกณฑ์ที่วัดผลได้
3. **A - Achievable (ทำได้จริง)** - ไม่ยากเกินไป ไม่ง่ายเกินไป
4. **R - Relevant (เกี่ยวข้อง)** - ตอบโจทย์ธุรกิจและผู้ใช้
5. **T - Time-bound (มีกรอบเวลา)** - ระบุช่วงเวลาที่ต้องทำเสร็จ



## Template สำหรับเขียน Requirement ใหม่

```markdown
| ID | Requirement | Description | Priority | Category | Stakeholder | Notes |
|----|-------------|-------------|----------|----------|-------------|-------|
| REQ-XXX | [ชื่อสั้นๆ] | [รายละเอียดชัดเจน ตาม SMART] | Must/Should/Could/Won't Have | [หมวดหมู่] | [ผู้ร้องขอ] | [หมายเหตุเพิ่มเติม] |
```

### ตัวอย่าง Requirement ที่ดี:
```
REQ-012 | Two-Factor Authentication | ระบบต้องรองรับการยืนยันตัวตนแบบ 2 ขั้นตอน (2FA) ผ่าน SMS หรือ Authenticator app เพื่อเพิ่มความปลอดภัย โดยผู้ใช้สามารถเปิด/ปิดได้เอง | Must Have | Security | CISO | รองรับ TOTP (RFC 6238)
```

### ตัวอย่าง Requirement ที่ไม่ดี:
```
REQ-XXX | ปลอดภัย | ระบบต้องปลอดภัย | Must Have | Security | - | -
```
**ปัญหา**: ไม่ชัดเจน (Not Specific), วัดผลไม่ได้ (Not Measurable), คลุมเครือ (Ambiguous)
