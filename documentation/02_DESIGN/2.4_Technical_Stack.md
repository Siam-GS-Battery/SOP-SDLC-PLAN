# 2.4 Technical Stack

## วิธีการเขียน
Technical Stack คือการกำหนดเทคโนโลยี เครื่องมือ และ framework ที่จะใช้ในการพัฒนาโปรเจกต์ ครอบคลุมทั้ง Frontend, Backend, Database, Infrastructure และเครื่องมือต่างๆ

---

## วัตถุประสงค์

การกำหนด Technical Stack ช่วยให้:
1. **ทีมมีความเข้าใจตรงกัน** - รู้ว่าจะใช้เทคโนโลยีอะไรบ้าง
2. **วางแผนการพัฒนาได้** - ประเมินเวลา ทรัพยากร และทักษะที่ต้องการ
3. **เลือกเครื่องมือที่เหมาะสม** - ตัดสินใจบนพื้นฐานของ requirements
4. **ลด Technical Debt** - เลือกเทคโนโลยีที่มี maintainability สูง
5. **Scale ได้ในอนาคต** - เลือกเทคโนโลยีที่รองรับการเติบโต

---

- Social media apps

| **Learning Curve** | Easy-Medium | Easy | Medium | Medium |

### เมื่อไหร่ควรใช้ Tailwind CSS?

#### ใช้ Tailwind CSS เมื่อ:
- 🎨 ต้องการ **Custom Design** ที่ไม่ซ้ำใคร (ไม่ต้องการ look เหมือน Bootstrap)
- ⚡ ต้องการ **Development Speed** สูง (ไม่ต้องสลับไปเขียน CSS file)
- 📦 ต้องการ **Bundle Size เล็ก** (Tailwind จะลบ CSS ที่ไม่ใช้ออกอัตโนมัติ)
- 📱 ต้องการ **Responsive Design** ที่ง่าย (เขียน `md:`, `lg:` prefix)
- 🎯 ต้องการ **Consistent Design System** (colors, spacing, typography)
- 🔧 ต้องการ **Customization** ง่าย (config ใน `tailwind.config.js`)
- 🚀 ทำ **Prototyping** หรือ **MVP** เร็ว

**ตัวอย่าง Use Cases**:
- Landing pages
- Marketing websites
- SaaS dashboards
- E-commerce platforms
- Admin panels
- Custom web applications

#### ใช้ Bootstrap เมื่อ:
- ⏰ ต้องการ **Launch เร็วมาก** ไม่ต้องการ custom มาก
- 📚 ทีมคุ้นเคย Bootstrap อยู่แล้ว
- 🎯 ต้องการ **Pre-built Components** เยอะ (Modals, Carousels, etc.)
- 💼 ทำ Internal tools หรือ Admin dashboards ที่ไม่เน้น unique design

#### ใช้ Material-UI เมื่อ:
- 🎨 ต้องการ **Material Design** style (Google-like)
- ⚛️ ใช้ **React** และต้องการ React components เต็มรูปแบบ
- 📦 ต้องการ **Pre-built Components** ที่ทำงานได้ทันที
- 🎭 ต้องการ **Theming System** ที่ powerful

#### ใช้ Styled Components เมื่อ:
- 🎨 ต้องการ **Dynamic Styling** based on props
- 🔐 ต้องการ **CSS Scoping** (no global CSS conflicts)
- 🎭 ต้องการ **Theming** ที่ซับซ้อน
- 💻 ต้องการเขียน CSS ในรูปแบบ traditional แต่ใน JavaScript

### Tailwind CSS Setup with React

#### Installation:

```bash
# Install Tailwind CSS
npm install -D tailwindcss postcss autoprefixer

# Initialize Tailwind config
npx tailwindcss init -p
```

#### Configuration (`tailwind.config.js`):

```javascript
/** @type {import('tailwindcss').Config} */
module.exports = {
  content: [
    "./src/**/*.{js,jsx,ts,tsx}",
  ],
  theme: {
    extend: {
      colors: {
        primary: '#3B82F6',
        secondary: '#8B5CF6',
      },
      fontFamily: {
        sans: ['Inter', 'sans-serif'],
      },
    },
  },
  plugins: [
    require('@tailwindcss/forms'),
    require('@tailwindcss/typography'),
  ],
}
```

#### Import in CSS (`src/index.css`):

```css
@tailwind base;
@tailwind components;
@tailwind utilities;

/* Custom styles */
@layer components {
  .btn-primary {
    @apply bg-blue-500 hover:bg-blue-700 text-white font-bold py-2 px-4 rounded;
  }
}
```

### Tailwind CSS Best Practices

#### ✓ DO:
1. **Use `@apply` for repeated patterns**
   ```css
   .btn {
     @apply px-4 py-2 rounded font-semibold;
   }
   ```

2. **Create custom components for complex UIs**
   ```jsx
   const Card = ({ children }) => (
     <div className="bg-white shadow-lg rounded-lg p-6">
       {children}
     </div>
   )
   ```

3. **Use Tailwind's design tokens**
   ```jsx
   // ✅ Good: Use spacing scale
   <div className="px-4 py-2 mb-4">

   // ❌ Bad: Arbitrary values
   <div className="px-[13px] py-[7px] mb-[18px]">
   ```

4. **Organize long className with clsx/classnames**
   ```jsx
   import clsx from 'clsx'

   <button className={clsx(
     'px-4 py-2 rounded font-semibold',
     'hover:bg-blue-700 focus:ring-2',
     isDisabled && 'opacity-50 cursor-not-allowed'
   )}>
   ```

#### ✗ DON'T:
1. **Don't mix Tailwind with traditional CSS too much**
2. **Don't use inline styles** (use Tailwind classes instead)
3. **Don't forget to purge unused CSS** (configure `content` in config)
4. **Don't override too many defaults** (defeats the purpose)

- ต้องการ launch เร็วหรือช้า?

### 4. Scalability & Maintainability
- ระบบต้อง scale ได้มากแค่ไหน?
- Maintain ง่ายหรือยาก?
- มี community support ดีหรือไม่?

### 5. Cost
- License cost (Enterprise software)
- Infrastructure cost (Cloud hosting)
- Developer cost (Hiring difficulty)

### 6. Ecosystem & Community
- มี library/plugin ให้ใช้เยอะหรือไม่?
- มี documentation ดีหรือไม่?

## Popular Technology Stack Combinations

### 1. MERN Stack
- **MongoDB** + **Express.js** + **React** + **Node.js**
- 💚 Best For: Startups, MVPs, JavaScript-only teams
- 💚 Pros: JavaScript ทั้ง stack, fast development
- 🔴 Cons: Lacks strong typing (ถ้าไม่ใช้ TypeScript)

### 2. MEAN Stack
- **MongoDB** + **Express.js** + **Angular** + **Node.js**
- 💚 Best For: Enterprise apps requiring structure
- 💚 Pros: TypeScript built-in, strong architecture
- 🔴 Cons: Steeper learning curve than React

### 3. LAMP Stack (Classic)
- **Linux** + **Apache** + **MySQL** + **PHP**
- 💚 Best For: Traditional web apps, WordPress sites
- 💚 Pros: Mature, stable, cheap hosting
- 🔴 Cons: Outdated for modern SPAs

### 4. JAMstack
- **JavaScript** + **APIs** + **Markup**
- 💚 Best For: Static sites, blogs, marketing sites
- 💚 Pros: Fast, secure, SEO-friendly
- 🔴 Cons: Limited dynamic features
- Examples: Next.js, Gatsby, Hugo + Netlify/Vercel

### 5. T3 Stack
- **TypeScript** + **tRPC** + **Tailwind CSS** + **Next.js** + **Prisma**
- 💚 Best For: Modern full-stack TypeScript apps
- 💚 Pros: End-to-end type safety, great DX
- 🔴 Cons: Newer stack, smaller community

### 6. Django Stack
- **Django** + **PostgreSQL** + **React/Vue**
- 💚 Best For: Data-heavy apps, content management
- 💚 Pros: Batteries-included, admin panel, ORM
- 🔴 Cons: Monolithic, Python-based

### 7. .NET Stack
- **ASP.NET Core** + **C#** + **SQL Server** + **Blazor/React**
- 💚 Best For: Enterprise applications, Windows ecosystem
- 💚 Pros: Strong typing, performance, Microsoft support
- 🔴 Cons: License cost (SQL Server), Windows-centric

## Best Practices

### ✓ DO:
1. **Document Your Choices** - อธิบายว่าทำไมเลือกเทคโนโลยีนี้
2. **Consider Team Skills** - อย่าเลือกเทคโนโลยีที่ทีมไม่เคยใช้ (เว้นแต่มีเวลาเรียน)
3. **Think Long-term** - เลือกเทคโนโลยีที่ maintain ได้นาน
4. **Use LTS Versions** - ใช้ Long-Term Support versions สำหรับ production
5. **Keep It Simple** - อย่าใช้เทคโนโลยีซับซ้อนเกินความจำเป็น
6. **Check Community Support** - เลือกที่มี community active
7. **Consider Hosting Cost** - คำนวณค่าใช้จ่าย infrastructure
8. **Prototype First** - ลองสร้าง POC (Proof of Concept) ก่อนตัดสินใจ
9. **Follow Industry Standards** - ใช้ best practices ของแต่ละเทคโนโลยี
10. **Plan for Monitoring** - มีเครื่องมือ monitoring/logging ตั้งแต่เริ่ม

### ✗ DON'T:
1. **Don't Follow Hype Blindly** - อย่าเลือกเพราะมันเป็น trend
2. **Don't Over-engineer** - อย่าใช้เทคโนโลยีซับซ้อนสำหรับโปรเจกต์เล็ก
3. **Don't Mix Too Many Technologies** - อย่าใช้หลายเทคโนโลยีจนสับสน
4. **Don't Ignore Security** - ต้องคำนึงถึงความปลอดภัย
5. **Don't Forget Testing Tools** - ต้องมีเครื่องมือทดสอบด้วย
6. **Don't Lock Into Proprietary Tech** - ระวัง vendor lock-in
7. **Don't Skip Version Control** - ต้องใช้ Git เสมอ

  └─ React Hook Form / Formik (Forms)

```
สำหรับ New Features & Real-time:
  └─ Supabase (PostgreSQL)
      ├─ Authentication
      ├─ Real-time subscriptions
      ├─ File storage
      └─ Auto-generated API

สำหรับ High-Performance Production:
  └─ AWS Aurora (MySQL/PostgreSQL)
      ├─ E-commerce transactions
      ├─ High-traffic APIs
      └─ Mission-critical data

สำหรับ Legacy Systems:
  └─ SQL Server + SSMS
      ├─ Existing ERP integration
      ├─ Enterprise reporting
      └─ .NET ecosystem integration
```

#### Backend Options:
```
Option 1: Supabase-first (Recommended for new projects)
  ├─ Supabase Auto API (Primary)
  └─ Supabase Edge Functions (Custom logic)

Option 2: Custom Backend (For complex business logic)
  ├─ Node.js + Express (if team knows JavaScript)
  ├─ .NET Core (if using SQL Server / Microsoft stack)
  └─ Connect to Supabase/Aurora/SQL Server as needed
```
