# 2.3 Interactive Prototype (Figma Prototype Link)

## วิธีการเขียน
Interactive Prototype คือ wireframe ที่เชื่อมโยงหน้าจอเข้าด้วยกัน สามารถคลิกและโต้ตอบได้ เพื่อใช้ในการทดสอบ User Flow และรับ feedback ก่อนเริ่มพัฒนาจริง

---

## วัตถุประสงค์

Interactive Prototype ช่วยให้:
1. **Test User Flow** - ทดสอบว่า flow ใช้งานง่ายหรือไม่
2. **Early Validation** - รับ feedback ก่อนเขียนโค้ดจริง
3. **Stakeholder Buy-in** - ให้ client/stakeholders เห็นภาพชัดเจน
4. **Identify Usability Issues** - หาปัญหาตั้งแต่เนิ่นๆ
5. **Save Development Time** - ลด rework หลังพัฒนาเสร็จ
6. **Communicate Vision** - ทีมเข้าใจวิสัยทัศน์เดียวกัน

---

## ระดับของ Prototype (Fidelity Levels)

### 1. **Paper Prototype** (Lowest Fidelity)
- **ลักษณะ**: วาดบนกระดาษ, hand-drawn
- **Interactions**: มือจัด "หน้าจอ" เปลี่ยน
- **ใช้เมื่อ**: Very early stage, quick validation
- **เวลา**: 30 นาที - 2 ชั่วโมง

### 2. **Low-Fi Digital Prototype** ← เราจะทำระดับนี้
- **ลักษณะ**: Grayscale wireframes + คลิกได้
- **Interactions**: Click to navigate, basic transitions
- **ใช้เมื่อ**: UAT, usability testing, client review
- **เวลา**: 2-4 ชั่วโมง
- **Tools**: Figma, Sketch, Adobe XD

### 3. **High-Fi Interactive Prototype**
- **ลักษณะ**: สีจริง, animations, micro-interactions
- **Interactions**: Advanced (hover, scroll, gestures)
- **ใช้เมื่อ**: Final validation before development
- **เวลา**: 1-3 วัน
- **Tools**: Figma, Protopie, Framer

**✅ สำหรับ Phase 2.3 เราทำ Low-Fi Digital Prototype (Grayscale + Clickable)**

## ความแตกต่าง: Wireframe vs Prototype

| Feature | Wireframe | Interactive Prototype |
|---|---|---|
| **Purpose** | Show layout & structure | Test user flow & interactions |
| **Interactions** | ไม่มี (static) | มี (clickable) |
| **Navigation** | ไม่ได้เชื่อม | เชื่อมหน้าจอเข้าด้วยกัน |
| **Testing** | Visual review | Usability testing |
| **Time** | เร็ว (ชั่วโมง) | นานกว่า (2-4 ชั่วโมง) |
| **Tool** | Figma/Sketch | Figma Prototype Mode |

## วิธีการสร้าง Interactive Prototype ใน Figma

### ขั้นตอนที่ 1: เตรียม Wireframes

**ก่อนเริ่มทำ Prototype ต้องมี:**
1. ✅ Wireframes ครบทุกหน้าจอ (จาก 2.2)
2. ✅ UX Flow Diagram (จาก 2.1)
3. ✅ User Stories & Acceptance Criteria

---

### ขั้นตอนที่ 2: สร้าง Interactions ใน Figma

#### 1. **เปิด Prototype Mode**
- กด **Shift + E** หรือคลิก "Prototype" tab ขวามือ
- Figma จะเปลี่ยนจาก Design mode → Prototype mode

#### 2. **Link Screens Together**
เชื่อมหน้าจอด้วย interactions:

**ตัวอย่าง: Login Flow**
```
Login Page → (Click "Login" button) → Dashboard
Login Page → (Click "Forgot Password") → Reset Password Page
Login Page → (Click "Sign Up") → Register Page
```

**วิธีทำ:**
1. เลือก element ที่จะคลิก (เช่น "Login" button)
2. ลาก connector (วงกลมสีฟ้า) ไปยัง frame ปลายทาง
3. ตั้งค่า interaction:
   - **On Click** (หรือ On Hover, On Drag)
   - **Navigate to** (หรือ Open overlay, Scroll to)
   - **Instant** (หรือ Dissolve, Move in, Push)

#### 3. **Common Interactions ที่ใช้บ่อย**

**Navigation:**
- **On Click → Navigate to**: ไปหน้าอื่น
- **On Click → Back**: กลับหน้าก่อนหน้า
- **On Click → Open overlay**: เปิด modal/popup

**State Changes:**
- **On Click → Change to**: เปลี่ยน state (Hover → Active)
- **On Hover → Change to**: แสดง hover state

**Scroll:**
- **On Click → Scroll to**: เลื่อนไปยังส่วนต่างๆ ในหน้า

---

### ขั้นตอนที่ 3: Add Transitions (Optional)

เพิ่ม animation transitions:

**Types of Transitions:**
- **Instant**: เปลี่ยนทันที (ไม่มี animation)
- **Dissolve**: Fade in/out (นุ่มนวล)
- **Move In/Out**: เลื่อนเข้า/ออก (mobile-like)
- **Push**: ดัน frame เก่าออก (slide transition)
- **Smart Animate**: Animate elements (advanced)

**แนะนำ:**
- ใช้ **Instant** สำหรับส่วนใหญ่ (เร็ว, ทดสอบง่าย)
- ใช้ **Dissolve** สำหรับ modal/overlay (duration: 300ms)
- เก็บ Smart Animate ไว้ทำ Hi-Fi prototype

---

### ขั้นตอนที่ 4: Define Starting Frame

กำหนดหน้าจอเริ่มต้น:
1. เลือก frame ที่เป็นหน้าแรก (เช่น Login Page)
2. คลิก "Set as starting frame" ใน Prototype panel

---

### ขั้นตอนที่ 5: Preview & Test

#### 1. **Test ใน Figma (Desktop)**
- กด **▶️ Play button** (มุมขวาบน)
- หรือกด **Shift + Space**
- ทดสอบคลิก navigate ทุก flow

#### 2. **Test บน Mobile (Figma Mirror)**
- ดาวน์โหลด Figma Mirror app (iOS/Android)
- Scan QR code หรือ login
- ทดสอบบน device จริง

#### 3. **Test กับทีม**
- แชร์ Prototype link
- ให้ทีมทดสอบและรับ feedback

---

### ขั้นตอนที่ 6: Add Hotspots & Annotations (Optional)

#### Hotspots:
แสดงพื้นที่ที่คลิกได้:
- เปิด Prototype → เปิด **Show hotspots** (Shift + H)
- จะเห็น blue overlay บนพื้นที่ที่คลิกได้

#### Annotations:
เพิ่มหมายเหตุใน prototype:
- ใช้ **Comments** (C key)
- เพิ่มคำอธิบาย interactions
- Tag คนในทีม (@mention)

### ขั้นตอนที่ 7: Share Prototype Link

1. **Get Shareable Link**:
   - คลิก **Share** (มุมขวาบน)
   - Copy "Prototype link"
   - ตั้งค่า permissions:
     - **Anyone with the link can view**
     - Enable comments (สำหรับ feedback)

2. **Share Options**:

   - **Can comment**: ดูและ comment ได้ (สำหรับ team)
   - **Can edit**: แก้ไขได้ (สำหรับ designers)

3. **Embed Settings** (Optional):
   - Show prototype settings (device frame, background)
   - Hotspot hints (แสดงหรือซ่อน hotspots)

## ตัวอย่าง Prototype Flows

### Example 1: User Login Flow

**Screens:**
1. Login Page
2. Dashboard (after successful login)
3. Error Modal (after failed login)
4. Forgot Password Page

**Interactions:**
```
[Login Page]
  ├─ "Login" button → Validate
  │   ├─ Success → [Dashboard]
  │   └─ Fail → [Error Modal]
  │       └─ "Try Again" → Back to [Login Page]
  │
  ├─ "Forgot Password" link → [Forgot Password Page]
  │   └─ "Back to Login" → [Login Page]
  │
  └─ "Sign Up" link → [Register Page]
```

### Example 2: Admin CRUD Flow

**Screens:**
1. Dashboard
2. User List
3. User Detail (View)
4. Edit User Form
5. Confirmation Modal
6. Success Toast

**Interactions:**
```
[Dashboard]
  └─ "Manage Users" → [User List]
      ├─ "Add User" button → [Create User Form]
      │   ├─ "Save" → Validation
      │   │   ├─ Valid → [Success Toast] → [User List (updated)]
      │   │   └─ Invalid → [Error messages]
      │   └─ "Cancel" → [User List]
      │
      ├─ Click user row → [User Detail]
      │   ├─ "Edit" button → [Edit User Form]
      │   │   └─ "Save" → [Success Toast] → [User Detail (updated)]
      │   │
      │   └─ "Delete" button → [Confirmation Modal]
      │       ├─ "Confirm" → [Success Toast] → [User List]
      │       └─ "Cancel" → [User Detail]
      │
      └─ "Back" → [Dashboard]
```

## Usability Testing with Prototype

### การทดสอบ Usability (Jakob Nielsen)

#### 1. **เตรียมการทดสอบ**
- **Participants**: 5-8 คน (มากกว่านี้ไม่คุ้ม)
- **Scenario**: เตรียม tasks ให้ทดสอบ
- **Environment**: เงียบ, ไม่มีรบกวน
- **Tools**: Screen recorder (optional)

#### 2. **Sample Test Tasks**
```
Task 1: Log in with your email and password
Task 2: View the dashboard and find total users
Task 3: Create a new user account
Task 4: Edit an existing user's email
Task 5: Delete a user account
Task 6: Export user list as PDF
```

#### 3. **During Testing**
- **Think Aloud**: ให้ผู้ทดสอบพูดออกมาว่ากำลังคิดอะไร
- **Observe**: สังเกต confusion, hesitation, errors
- **Don't Help**: ไม่ช่วย ไม่บอก (ยกเว้นติดมาก)
- **Take Notes**: บันทึกปัญหาที่พบ

#### 4. **After Testing**
- **Debrief**: ถามความรู้สึก, ความยาก
- **Collect Feedback**: รับ feedback เพิ่มเติม
- **Analyze Results**: สรุปปัญหาที่พบบ่อย
- **Prioritize Fixes**: แก้ปัญหาสำคัญก่อน

## Best Practices

### ✓ DO:
1. **Start Simple** - เริ่มจาก Happy Path ก่อน
2. **Test Early** - ทดสอบตั้งแต่เนิ่นๆ อย่ารอให้เสร็จหมด
3. **Use Real Content** - ใช้ข้อความจริง ไม่ใช่ Lorem Ipsum
4. **Include Error States** - ต้องมี error handling
5. **Think Mobile-First** - ทำ mobile prototype ด้วย
6. **Keep Interactions Simple** - ไม่ต้อง animate ทุกอย่าง
7. **Document Interactions** - เขียน spec ว่า interaction ไหนทำอะไร
8. **Test with Users** - ทดสอบกับผู้ใช้จริง 5-8 คน
9. **Iterate Based on Feedback** - แก้ไขตาม feedback
10. **Share with Team** - ให้ทีมทดสอบและรับความเห็น

### ✗ DON'T:
1. **Don't Over-animate** - ไม่ต้อง animate ทุกอย่าง (ยังเป็น Lo-Fi)
2. **Don't Skip Error Cases** - Error handling สำคัญมาก
3. **Don't Make It Pixel-Perfect** - ยังไม่ต้องละเอียดมาก
4. **Don't Test Alone** - ต้องให้ user ทดสอบด้วย
5. **Don't Ignore Feedback** - Feedback มีค่า แก้ไขมัน
6. **Don't Build Everything** - Prototype แค่ core flows
7. **Don't Add Colors Yet** - เก็บไว้ทำ Hi-Fi mockup
8. **Don't Forget Mobile** - Mobile prototype สำคัญเท่า desktop

## Design Sprint (Jake Knapp, Google Ventures)

### 5-Day Sprint for Prototyping:

**Monday - Map**: วางแผน, กำหนด goal
**Tuesday - Sketch**: วาด solutions
**Wednesday - Decide**: เลือก solution ที่ดีที่สุด
**Thursday - Prototype**: สร้าง prototype
**Friday - Test**: ทดสอบกับ users

**ใน Phase 2 เราทำ Thursday-Friday:**
- Thursday: สร้าง Interactive Prototype
- Friday: UAT with stakeholders/users

## Tips สำหรับ Prototype ที่ดี

### 1. **Focus on User Flow**
- Prototype ต้องเน้นที่ flow หลักที่ user จะใช้
- ไม่ต้องทำทุก feature ใน prototype

### 2. **Keep It Realistic**
- ใช้ข้อความจริง, data จริง (ไม่ใช่ Lorem Ipsum)
- แต่ยังไม่ต้อง perfect (ยังเป็น grayscale)

### 3. **Test Early, Test Often**
- ทดสอบตั้งแต่เนิ่นๆ
- แก้ไขและทดสอบซ้ำ (iterate)

### 4. **Get Diverse Feedback**
- Product Owner: Business perspective
- Developers: Technical feasibility
- Designers: UX/UI perspective
- Users: Usability

### 5. **Document Everything**
- บันทึก interactions
- เก็บ feedback
- Track changes (version control)

**Prototype ที่ดีทำให้ทุกคนเห็นภาพเดียวกัน และลดความเสี่ยงในการพัฒนา 🚀**
