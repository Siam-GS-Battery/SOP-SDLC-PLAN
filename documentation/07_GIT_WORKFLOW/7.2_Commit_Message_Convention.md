# 7.2 Commit Message Convention - มาตรฐานการเขียน Commit Message

## ภาพรวม

เอกสารนี้กำหนดมาตรฐานการเขียน Commit Message ตาม **Conventional Commits** เพื่อให้ประวัติการเปลี่ยนแปลงอ่านง่ายและสร้าง changelog อัตโนมัติได้

## รูปแบบ Commit Message

### โครงสร้าง

```
<type>(<scope>): <subject>

[optional body]

[optional footer]
```

### ส่วนประกอบ

| ส่วน | Required | คำอธิบาย |
|------|----------|----------|
| **type** | ✅ | ประเภทของการเปลี่ยนแปลง |
| **scope** | ❌ | ส่วนที่ได้รับผลกระทบ |
| **subject** | ✅ | สรุปการเปลี่ยนแปลงสั้นๆ |
| **body** | ❌ | รายละเอียดเพิ่มเติม |
| **footer** | ❌ | Breaking changes, issue references |

## Commit Types

### Primary Types

| Type | Emoji | ใช้เมื่อ | ตัวอย่าง |
|------|-------|---------|---------|
| `feat` | ✨ | เพิ่ม feature ใหม่ | เพิ่มหน้า login |
| `fix` | 🐛 | แก้ bug | แก้ปัญหา form validation |
| `docs` | 📝 | แก้ไขเอกสาร | อัปเดต README |
| `style` | 💄 | แก้ไข formatting (ไม่กระทบ logic) | แก้ indentation |
| `refactor` | ♻️ | ปรับปรุง code (ไม่เพิ่ม feature/ไม่แก้ bug) | แยก function |
| `test` | ✅ | เพิ่ม/แก้ไข tests | เพิ่ม unit test |
| `chore` | 🔧 | งาน maintenance | อัปเดต dependencies |

### Additional Types

| Type | Emoji | ใช้เมื่อ |
|------|-------|---------|
| `perf` | ⚡ | ปรับปรุง performance |
| `ci` | 👷 | แก้ไข CI/CD configuration |
| `build` | 📦 | แก้ไข build system |
| `revert` | ⏪ | revert commit ก่อนหน้า |

## Scope

Scope ระบุส่วนของระบบที่ได้รับผลกระทบ

### ตัวอย่าง Scopes

| Scope | ความหมาย |
|-------|----------|
| `auth` | Authentication/Authorization |
| `api` | API endpoints |
| `ui` | User Interface |
| `db` | Database |
| `config` | Configuration |
| `deps` | Dependencies |

## ตัวอย่าง

### ✅ Good Commits

```bash
# Feature ใหม่
feat(auth): add Google OAuth login

# แก้ Bug
fix(api): resolve null pointer in user service

# Documentation
docs(readme): update installation instructions

# Refactoring
refactor(utils): extract date formatting to helper

# Style (formatting)
style(components): fix indentation in Button.tsx

# Test
test(auth): add unit tests for login validation

# Chore
chore(deps): upgrade React to v18.2

# Performance
perf(api): add caching for user queries

# Breaking Change
feat(api)!: change response format for /users endpoint

BREAKING CHANGE: response now returns { data: users } instead of users array
```

### ❌ Bad Commits

```bash
# ไม่มี type
update code

# ไม่ชัดเจน
fix: fix bug

# ยาวเกินไป
feat: add new feature that allows users to login with their Google account and also Facebook account

# ภาษาไทย (ไม่แนะนำ)
feat: เพิ่มหน้า login

# หลาย changes ใน commit เดียว
feat: add login and fix navbar and update readme
```

## Subject Guidelines

### กฎการเขียน Subject

| กฎ | ตัวอย่างถูก | ตัวอย่างผิด |
|----|------------|------------|
| ใช้ imperative mood | `add feature` | `added feature` |
| ขึ้นต้นด้วยตัวพิมพ์เล็ก | `add login page` | `Add login page` |
| ไม่ใส่จุดท้าย | `fix bug` | `fix bug.` |
| ไม่เกิน 50 ตัวอักษร | `add user auth` | `add user authentication feature with validation` |

### Imperative Mood

เขียนเหมือนคำสั่ง:
- ✅ "add feature" (ไม่ใช่ "added" หรือ "adding")
- ✅ "fix bug" (ไม่ใช่ "fixed" หรือ "fixing")
- ✅ "update docs" (ไม่ใช่ "updated" หรือ "updating")

---

## Body Guidelines

ใช้ body เมื่อต้องการอธิบายเพิ่มเติม:

```bash
fix(auth): resolve session timeout issue

The session was expiring too quickly because the timeout
was set in milliseconds instead of seconds.

- Changed timeout from 3600 to 3600000
- Added unit test to verify timeout behavior
```

### เมื่อไหร่ควรใช้ Body

- การเปลี่ยนแปลงซับซ้อน
- ต้องอธิบาย "ทำไม" ไม่ใช่แค่ "อะไร"
- Breaking changes

---

## Footer Guidelines

### Issue References

```bash
feat(auth): add password reset flow

Closes #123
Refs #456
```

### Breaking Changes

```bash
feat(api)!: change user endpoint response format

BREAKING CHANGE: The /api/users endpoint now returns
{ data: users, meta: { total } } instead of just users array.

Migration: Update all API calls to access users via response.data
```

## Git Hooks (Optional)

### ติดตั้ง commitlint

```bash
# ติดตั้ง
npm install --save-dev @commitlint/cli @commitlint/config-conventional

# สร้าง config
echo "module.exports = { extends: ['@commitlint/config-conventional'] };" > commitlint.config.js
```

### ติดตั้ง husky

```bash
npm install --save-dev husky
npx husky install
npx husky add .husky/commit-msg 'npx --no -- commitlint --edit "$1"'
```

## Best Practices

### ✅ ควรทำ

1. **Commit บ่อยๆ** - แต่ละ commit ควรเป็น logical unit
2. **Atomic commits** - หนึ่ง commit = หนึ่งการเปลี่ยนแปลง
3. **Review ก่อน commit** - ใช้ `git diff` ตรวจสอบ
4. **เขียนให้คนอื่นเข้าใจ** - คิดว่าคนอื่นจะอ่าน

### ❌ ไม่ควรทำ

1. **Commit หลาย changes พร้อมกัน**
2. **เขียน message ไม่ชัดเจน** เช่น "fix", "update", "wip"
3. **Commit ไฟล์ที่ไม่เกี่ยวข้อง**
4. **Commit secrets หรือ credentials**

## Quick Reference

### Template

```
<type>(<scope>): <subject>
│       │         │
│       │         └─⫸ สรุปสั้นๆ (imperative, lowercase, no period)
│       │
│       └─⫸ Scope: auth|api|ui|db|config|deps (optional)
│
└─⫸ Type: feat|fix|docs|style|refactor|test|chore|perf|ci|build|revert
```

### Cheat Sheet

```bash
# Features
feat(scope): add new feature
feat(scope)!: add breaking change feature

# Bug fixes
fix(scope): resolve issue with X

# Documentation
docs(scope): update README

# Refactoring
refactor(scope): restructure X component

# Tests
test(scope): add tests for X

# Chores
chore(deps): update dependencies
```
